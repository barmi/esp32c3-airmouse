# 하드웨어

[ESP32-C3-DevKit-RUST-2](https://github.com/esp-rs/esp-rust-board) (esp-rust-board) 보드를 씁니다. 커서 이동은 온보드 부품만으로 동작하고, 클릭·스크롤 버튼 4개와 배터리는 직접 연결해야 합니다.

## 구성 요소

| 구성 요소 | 사양 | 연결 |
|---|---|---|
| MCU | ESP32-C3 (RISC-V 160MHz, 4MB Flash, BLE 5.0) | — |
| IMU | ICM-42670-P (6축 자이로+가속도) | I2C 주소 `0x68` |
| 온습도 센서 | SHTC3 (이 프로젝트에서는 미사용) | I2C 주소 `0x70` |
| I2C 버스 | 400kHz | SDA=`GPIO7`, SCL=`GPIO8` |
| RGB LED | WS2812 (상태 표시용) | `GPIO2` |
| 단색 LED | (미사용) | `GPIO10` |
| BOOT 버튼 | 온보드 → 자이로 재캘리브레이션 | `GPIO9` (active-low, 내부 풀업) |
| 클릭·스크롤 버튼 | **외부 택트 스위치 4개** (직접 배선) | `GPIO3`~`GPIO6` |
| 전원 | USB-C, LiPo 충전(MCP73831) | 배터리 전압 측정 회로 없음 |

## 주의: RUST-2의 I2C 핀은 문서와 다릅니다

**공식 문서에 적힌 SDA=GPIO10은 RUST-1 값이며, RUST-2에서는 동작하지 않습니다.**

RUST-2 개정판에서 유저 LED가 `GPIO7` → `GPIO10`으로 옮겨가면서, 그 자리를 I2C SDA가 넘겨받았습니다. 그런데 [Espressif 공식 사용자 가이드](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32c3/esp32-c3-devkit-rust-2/user_guide.html)와 [esp-rust-board README](https://github.com/esp-rs/esp-rust-board)의 핀 테이블에는 여전히 RUST-1 값(SDA=GPIO10, LED=GPIO7)이 실려 있습니다. 두 문서 모두 "유저 LED가 GPIO10으로 바뀌었다"는 변경 사항은 본문에 적어두고서 정작 핀 테이블은 갱신하지 않았습니다.

| | RUST-1 | **RUST-2 (이 프로젝트)** |
|---|---|---|
| I2C SDA | GPIO10 | **GPIO7** |
| 유저 LED | GPIO7 | GPIO10 |

이 값은 실제 보드의 I2C 스캔으로 먼저 확인했고, 이후 [RUST-2 공식 회로도 Rev 2.0](https://dl.espressif.com/public/esp32-c3-devkit-rust-2-schematic.pdf)으로 검증했습니다. 회로도의 실제 넷 이름은 `IO7_SDA`, `IO8_SCL`이고 유저 LED(D2)는 `IO10`에 연결되어 있습니다.

흥미롭게도 **회로도 자체에도 같은 오류가 남아 있습니다.** LED 블록의 제목은 여전히 `Regular on GPIO7`이라고 적혀 있지만, 실제 배선은 `IO10 → R10 → D2`입니다. 넷은 고쳤는데 설명 텍스트를 갱신하지 않은 것이고, 문서의 핀 테이블 오류도 같은 경위로 보입니다.

문서대로 GPIO10을 쓰면 IMU가 ACK하지 않고 다음 에러가 납니다.

```
IMU 오류: BusError(I2cError { kind: NoAcknowledge(Unknown), cause: ESP_FAIL })
```

### 핀맵을 직접 확인하는 방법

다른 보드 개정판을 쓰거나 배선이 의심스러우면, GPIO 조합을 순회하며 IMU(`0x68`)와 SHTC3(`0x70`)가 응답하는 쌍을 찾는 것이 가장 빠릅니다.

이때 **조합마다 `gpio_reset_pin()`으로 GPIO 매트릭스를 초기화해야 합니다.** ESP32의 GPIO 매트릭스는 이전 시도의 I2C 신호 라우팅을 핀에 남겨두기 때문에, 초기화하지 않으면 실제로는 연결되지 않은 조합까지 전부 ACK하는 것처럼 보입니다. 실제로 이 프로젝트 브링업 중 초기화 없이 스캔했을 때 10개 조합이 모두 "발견"으로 잡혔고, 초기화를 넣자 정답 하나(SDA=GPIO7, SCL=GPIO8)만 남았습니다.

## 왜 BLE인가 — USB HID는 불가능합니다

ESP32-C3의 USB 포트는 **Serial/JTAG 전용**입니다. USB OTG 컨트롤러가 없어서 USB HID 마우스로 동작할 수 없습니다. (USB OTG는 ESP32-S2/S3에만 있습니다.)

그래서 이 프로젝트는 **BLE HID(HOGP, HID over GATT Profile)** 로 구현합니다. USB 케이블은 전원 공급과 펌웨어 플래싱/디버깅 용도로만 쓰입니다.

## ICM-42670-P 특성

### 축 방향

USB 커넥터가 앞(모니터 쪽)을 향하도록 쥔 기준입니다. 실제 보드를 움직여 로그로 확인한 값입니다.

| 자이로 축 | 회전 | 용도 |
|---|---|---|
| **Z** | yaw — 손목 좌우 회전 | 커서 X (좌우) |
| **X** | pitch — 손목 상하 기울임 | 커서 Y (상하) |
| Y | roll — 옆으로 눕히기 | 미사용 |

### 전원 인가 직후 포화값 주의

자이로는 스핀업이 끝나기 전까지 **풀스케일 포화값(±2000dps)** 을 출력합니다. 부팅 직후 첫 샘플에서 이런 값이 나옵니다.

```
gyro[dps] x=-1998.05 y=-1998.05 z=-1998.05
```

캘리브레이션에서 이 값이 평균에 섞이면 치명적입니다. 200샘플 평균에 포화 샘플이 **2개만** 들어가도 바이어스가 20dps 틀어지고, 그러면 정지 상태에서도 커서가 계속 흐릅니다.

실제로 브링업 중 이 문제로 바이어스가 `x=-19.31, z=-13.40`(정상값의 100배)으로 측정된 적이 있습니다. 현재 코드는 앞 샘플을 버리는 것에 더해 **|ω| > 20dps인 샘플을 평균에서 제외**하여 이를 막습니다 ([firmware/src/imu.rs](../firmware/src/imu.rs)의 `calibrate_gyro`).

### 설정값

| 항목 | 값 | 이유 |
|---|---|---|
| 전원 모드 | 6축 low-noise | 자이로 + 가속도 모두 활성 |
| 자이로 풀스케일 | ±2000dps | 빠른 손동작에도 포화되지 않는 최대 범위 |
| 자이로 ODR | 200Hz | 메인 루프(100Hz)보다 높게 잡아 항상 최신 값 확보 |

### 온도 드리프트는 보상할 필요가 없습니다

MEMS 자이로는 온도에 따라 영점이 흔들리므로 온도 보상을 고려할 수 있지만, 이 센서에서는 실익이 없습니다. [데이터시트](https://cdn-shop.adafruit.com/product-files/5787/DS-000451-ICM-42670-P-v1.0.pdf) 사양은 다음과 같습니다.

| 항목 | 값 |
|---|---|
| 초기 영점 오차 (25°C) | ±1 °/s |
| **영점의 온도 변동** | **±0.015 °/s/°C** (-40~+85°C, 보드 레벨) |

사용 중 보드가 20°C 오르더라도 영점 이동은 `20 × 0.015 = 0.3 °/s`입니다. 현재 데드존이 **2.0 °/s**이므로 여유 있게 흡수됩니다. 40°C가 변해도 0.6 °/s로 여전히 데드존 안입니다.

따라서 온도 센서를 읽어 보상하는 로직은 불필요합니다. 만약 언젠가 필요해지더라도 주변 공기를 재는 SHTC3가 아니라 **자이로 다이 온도를 재는 IMU 내장 온도 센서**(`icm42670` 크레이트의 `temperature()`)를 써야 합니다.

## 전원

- USB-C (PD 미지원)
- LiPo 배터리 충전: MCP73831, 충전 전류 100mA 고정(PROG 저항 10kΩ), 4.2V까지
- **보호회로 내장 배터리를 쓰세요.** MCP73831에는 과방전 보호가 없습니다.

### 배터리는 연결만 하면 됩니다

보드에 **USB/배터리 자동 절체 회로**가 이미 들어 있습니다. 배터리를 `BAT+`/`BAT−` 패드에 연결하는 것만으로 충전과 주전원 공급이 모두 됩니다. 다이오드나 스위치를 추가할 필요가 없습니다.

```
VBUS ──┬─────────────── Q1 게이트 (DMG3415U, P-MOSFET)
       │                  │
       ├──▶|── D4 ────────┼──── +5V (시스템 레일) ── 버크 ── 3V3
       │   B5819W         │
       │              +BATT (소스)
      R15 100kΩ
       │
      GND
```

| 상황 | 게이트 | Q1 | 시스템 전원 | 충전 |
|---|---|---|---|---|
| USB 연결 | VBUS = 5V | OFF | USB (D4 경유) | **진행** |
| USB 분리 | R15가 GND로 당김 | ON | **배터리** | — |

USB를 꽂으면 게이트가 배터리 전압보다 높아져 P-MOSFET이 꺼지고 배터리가 시스템에서 분리되며, 그동안 충전기가 배터리를 충전합니다. USB를 빼면 R15가 게이트를 접지로 내려 MOSFET이 켜지고 배터리가 시스템을 구동합니다. **전환은 자동이고 끊김이 없습니다.**

### 파워 스위치는 ENABLE 핀에 답니다

버크 컨버터(U5, SY8088)의 EN 핀은 R1 10kΩ으로 +5V에 풀업되어 있고, 그 노드가 헤더의 **`EN`** 핀(실크 표기)으로 나와 있습니다.

**`EN` ↔ `GND`를 연결하면 버크가 셧다운되어 3.3V 레일이 내려가고 보드가 완전히 꺼집니다.**

```
EN 핀 ────[ 래칭 스위치 ]──── GND     (닫으면 꺼짐)
```

| | ENABLE 방식 | 배터리 선 차단 방식 |
|---|---|---|
| 스위치에 흐르는 전류 | 약 0.4mA (신호 수준) | 전체 부하 전류 (피크 200~300mA) |
| **끈 상태에서 충전** | **가능** | 불가 |
| 끈 상태 소모 | 약 0.4mA (R1 경유) | 0 |

일상적으로는 ENABLE 방식이 낫습니다. 끈 채로 충전할 수 있고 작은 스위치로 충분합니다. 다만 900mAh 배터리 기준 0.4mA면 약 100일이므로, **장기 보관할 때는 배터리를 분리**하세요.

> **모멘터리 택트 스위치는 파워 스위치로 쓸 수 없습니다.** 손을 떼면 돌아오므로 슬라이드/토글 같은 **래칭 스위치**가 필요합니다. 논리가 반전(닫힘=꺼짐)이라 스위치의 ON/OFF 표시는 반대로 붙이세요.

> **`RST`와 `EN`은 다릅니다.** 왼쪽 헤더의 `RST`는 ESP32 리셋(CHIP_PU)이라 눌러도 보드 전원은 살아 있습니다. 전원을 끊는 것은 오른쪽 헤더의 `EN`입니다.

### 딥슬립을 쓰면 스위치가 필요 없습니다

모멘터리 버튼으로 딥슬립에 들어가고 나오게 하면 래칭 스위치 없이 소프트 전원 버튼을 만들 수 있습니다. 단 **ESP32-C3는 GPIO0~GPIO5에서만 딥슬립 기상이 가능**합니다(`SOC_GPIO_DEEP_SLEEP_WAKE_VALID_GPIO_MASK`). 현재 버튼 배치에서 GPIO3/4/5는 되고 GPIO6은 안 됩니다. 버크 자체 대기 전류(40µA)와 충전기 소모는 남습니다. 자세한 건 전원 관리 이슈에서 다룹니다.

### 핀 헤더 전체 배치

| 왼쪽 헤더 | | 오른쪽 헤더 | |
|---|---|---|---|
| 1 | `RST` (ESP32 리셋) | 30 | `BAT+` (충전기 패드) |
| 2 | `3V3` | 29 | `BAT−` (충전기 패드) |
| 3 | N/C | 28 | `BAT+` (=VBAT) |
| 4 | **`GND`** | 27 | **`EN`** (버크 enable) |
| 5 | `GPIO0` (ADC1) | 26 | `5V` (=VBUS) |
| 6 | `GPIO1` (ADC1) | 25~21 | SPI 플래시 전용 (사용 불가) |
| 7 | `GPIO2` — WS2812 | 20 | `GPIO18` — USB D− |
| 8 | **`GPIO3`** — 좌클릭 | 19 | `GPIO19` — USB D+ |
| 9 | **`GPIO4`** — 우클릭 | 18 | (미연결) |
| 10 | **`GPIO5`** — 스크롤↑ | 17 | (미연결) |
| 11 | **`GPIO6`** — 스크롤↓ | | |
| 12 | `GPIO7` — I2C SDA | | |
| 13 | `GPIO8` — I2C SCL | | |
| 14 | `GPIO21` — UART TX | | |
| 15 | `GPIO20` — UART RX | | |
| 16 | `GPIO9` — BOOT 버튼 | | |

**GND는 왼쪽 헤더 4번 하나뿐입니다.** 스위치 5개(클릭 4 + 파워 1)의 GND를 모두 여기로 모아야 하므로, 작은 만능기판에 GND 버스를 만들거나 전선을 데이지체인으로 잇는 편이 낫습니다. `BAT−` 패드도 전기적으로 GND라 여유가 필요하면 그쪽을 쓸 수 있습니다.

## 충전 회로와 배터리 상태

충전 IC(U6, MCP73831T-2ACI/OT)의 상태 핀은 **LED 하나만 구동하고 GPIO에는 연결되어 있지 않습니다.**

```
U6.STAT ──[R14 1kΩ]──▶|── VBUS
                      D3 (빨간 LED)
```

[RUST-2 공식 회로도 Rev 2.0](https://dl.espressif.com/public/esp32-c3-devkit-rust-2-schematic.pdf)에서 확인한 실제 연결입니다. STAT 넷에는 넷 이름조차 없고 R14 외에는 아무것도 붙어 있지 않습니다. 따라서:

- **펌웨어는 충전 중/완료를 알 수 없습니다.** 빨간 LED(D3)가 유일한 표시 수단이며, 이는 하드웨어가 직접 구동합니다.
- **배터리 전압도 읽을 수 없습니다.** 전압 분배 회로가 없습니다. HID 배터리 서비스에는 100% 고정값을 보고합니다.

### 펌웨어에서 읽으려면 (개조)

헤더에 **VBAT(28번)** 과 **VBUS(26번)** 핀이 나와 있으므로, 각각 분압해서 ADC로 읽으면 충전 상태를 추정할 수 있습니다. **GPIO0과 GPIO1**을 쓰세요 — ADC1 채널 중 버튼에 쓰지 않고 남겨둔 두 핀입니다 (ADC2는 공장 캘리브레이션이 없습니다).

| VBUS | VBAT | 판정 |
|---|---|---|
| 없음 | — | 배터리 구동 (전압으로 잔량 추정) |
| 있음 | 4.15V 미만 | 충전 중 |
| 있음 | 4.2V 근처에서 정체 | 충전 완료 |

배터리는 최대 4.2V, VBUS는 5V라서 3.3V ADC 입력 범위를 넘습니다. 2:1 분압(예: 100kΩ + 100kΩ)이 필요합니다.

> **STAT 핀을 직접 GPIO에 연결하지 마세요.** 충전이 끝나면 STAT가 고임피던스가 되어 해당 노드가 LED를 통해 VBUS(5V)까지 올라갑니다. 3.3V GPIO에 직접 연결하면 손상됩니다.

### USB 연결 감지는 충전 감지가 아닙니다

ESP-IDF에 `usb_serial_jtag_is_connected()`가 있지만, 이것은 호스트가 보내는 SOF 패킷으로 **PC 연결**을 판정합니다. 공식 문서가 명시하듯 보조배터리나 충전기에 꽂은 경우는 SOF가 없어 **연결로 잡히지 않습니다.** 충전 상태 표시에는 쓸 수 없습니다.

## 클릭과 스크롤 버튼 배선

우클릭과 스크롤은 외부 택트 스위치 4개로 구현합니다. 보드에 기본 탑재된 버튼이 아니므로 직접 연결해야 합니다.

| 기능 | GPIO | 헤더 위치 |
|---|---|---|
| 좌클릭 | `GPIO3` | 왼쪽 헤더 |
| 우클릭 | `GPIO4` | 왼쪽 헤더 |
| 스크롤 ↑ | `GPIO5` | 왼쪽 헤더 |
| 스크롤 ↓ | `GPIO6` | 왼쪽 헤더 |

이 조합을 고른 이유는 **GPIO0/1을 비워두기 위해서**입니다. 그 둘은 ADC1 채널이라 [배터리 전압 감지 개조](#펌웨어에서-읽으려면-개조)에 필요합니다. GPIO6은 ADC가 없는 핀이라 디지털 입력으로 쓰기에 적합합니다.

배선은 스위치마다 동일합니다.

```
GPIO핀 ────[ 택트 스위치 ]──── GND
              (대각선 두 핀)
```

**외부 풀업 저항은 필요 없습니다.** 펌웨어가 내부 풀업을 켜므로 안 눌렀을 때 HIGH, 누르면 LOW가 됩니다.

### 택트 스위치 핀 고르기

4핀 택트 스위치는 전기적으로는 2핀입니다. **같은 변에 있는 두 핀은 내부에서 이미 연결**되어 있고, 누르면 두 쌍이 이어집니다.

**대각선으로 마주보는 두 핀을 쓰면 방향에 관계없이 항상 맞습니다.** 헷갈리면 멀티미터 도통 모드로 확인하세요 — 누르지 않았는데 도통되면 같은 쌍이므로 다른 핀을 고릅니다.

### GND가 하나뿐입니다

핀 헤더에 GND 핀이 하나밖에 없습니다. 스위치 4개의 GND 쪽 다리를 서로 이어서 한 가닥으로 GND 핀에 연결하세요.

## GPIO9(BOOT 버튼) 주의

GPIO9는 부팅 스트래핑 핀입니다. 동작 중 입력으로 쓰는 데는 문제가 없지만, **버튼을 누른 채로 리셋하면 다운로드 모드로 진입**합니다. 펌웨어가 실행되지 않는다면 버튼에서 손을 떼고 다시 리셋하세요.

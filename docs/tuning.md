# 튜닝 가이드

커서 움직임이 손에 맞지 않을 때 조정하는 방법입니다. 커서 관련 상수는 [firmware/src/mapping.rs](../firmware/src/mapping.rs), 절전 관련 상수는 [firmware/src/power.rs](../firmware/src/power.rs) 맨 위에 모여 있습니다.

바꾼 뒤에는 다시 빌드해서 플래시해야 합니다.

```bash
cd firmware && cargo run
```

## 상수 한눈에 보기

| 상수 | 기본값 | 역할 |
|---|---|---|
| `GAIN` | 0.18 | 감도. 각속도(dps)에 곱해 커서 이동량을 만듭니다 |
| `DEADZONE_DPS` | 2.0 | 이 값 미만의 각속도는 무시 (드리프트/손떨림 차단) |
| `YAW_SIGN` | -1.0 | 좌우 방향 부호 |
| `PITCH_SIGN` | -1.0 | 상하 방향 부호 |
| `SCROLL_SIGN` | -1 | 스크롤 방향 부호 (macOS 자연스러운 스크롤 기준) |
| `SCROLL_REPEAT_DELAY_MS` | 300 | 스크롤 버튼을 누르고 있을 때 연속 스크롤이 시작되기까지 |
| `SCROLL_REPEAT_MS` | 100 | 연속 스크롤 간격 |
| `ABS_FILTER_MIN_CUTOFF_HZ` | 1.0 | 절대 모드: 정지 시 떨림 제거 강도 |
| `ABS_FILTER_BETA` | 0.3 | 절대 모드: 빠른 동작의 지연 감소 정도 |
| `ABS_YAW_GATE_DPS` | 0.3 | 절대 모드: 이보다 느린 좌우 회전은 무시 (드리프트 방지) |

## 감도 조정

`GAIN`만 바꾸면 됩니다.

```rust
pub const GAIN: f32 = 0.18;
```

| 증상 | 조정 |
|---|---|
| 커서가 **둔하다** — 화면을 가로지르려면 손을 크게 휘둘러야 함 | 값을 **올립니다** (0.25 → 0.35 …) |
| 커서가 **너무 민감하다** — 작은 손떨림에도 크게 튐 | 값을 **내립니다** (0.12 → 0.08 …) |

한 번에 크게 바꾸기보다 1.5배씩 조정하며 좁혀가는 편이 빠릅니다. 기본값 0.18은 0.10이 "너무 둔하다"는 피드백을 받아 올린 값입니다.

계산은 이렇습니다: 100Hz 루프에서 손목을 90dps로 돌리면 `90 × 0.18 = 16.2` 카운트/리포트 → 초당 약 1600카운트가 나갑니다.

> 호스트 쪽 마우스 속도 설정도 함께 작용합니다. macOS의 **시스템 설정 → 마우스 → 추적 속도**를 먼저 조정해 보고, 그래도 부족할 때 `GAIN`을 건드리는 것이 좋습니다.

## 방향 뒤집기

보드를 쥔 방향이 기준(USB 커넥터가 모니터 쪽)과 다르거나, 취향에 맞지 않을 때 부호만 뒤집습니다.

```rust
pub const YAW_SIGN: f32 = -1.0;   // 좌우
pub const PITCH_SIGN: f32 = -1.0; // 상하
```

| 증상 | 조정 |
|---|---|
| 오른쪽으로 돌리면 커서가 왼쪽으로 감 | `YAW_SIGN`을 `1.0`으로 |
| 앞을 들면 커서가 아래로 감 | `PITCH_SIGN`을 `1.0`으로 |

두 축은 독립적이라 한쪽만 뒤집어도 됩니다.

## 정지 시 커서가 흐를 때

먼저 **보드를 책상에 내려놓은 채로 전원을 다시 넣어** 보세요. 대부분 캘리브레이션 중 보드가 움직여서 생기는 문제이고, 이것으로 해결됩니다 ([사용법의 캘리브레이션](usage.md#캘리브레이션) 참고).

재부팅해도 계속 흐른다면 데드존을 올립니다.

```rust
pub const DEADZONE_DPS: f32 = 2.0;
```

3.0 → 4.0 순으로 올려보세요. 다만 데드존을 올릴수록 **아주 느린 의도적 움직임도 함께 무시**되므로, 흐름이 멈추는 최소값에서 멈추는 것이 좋습니다.

데드존은 문턱을 넘는 순간 값이 튀지 않도록, 문턱만큼을 빼서 0에서 연속으로 이어지게 구현되어 있습니다. 즉 2.0dps에서 갑자기 움직이기 시작하는 게 아니라 부드럽게 시작합니다.

## 스크롤 조정

스크롤 버튼은 톡 누르면 한 칸, 계속 누르고 있으면 연속으로 움직입니다. 키보드 키 반복과 같은 방식입니다.

```rust
pub const SCROLL_SIGN: i8 = -1;
pub const SCROLL_REPEAT_DELAY_MS: u32 = 300;
pub const SCROLL_REPEAT_MS: u32 = 100;
```

기본값 `-1`은 macOS 기본 설정에 맞춘 값입니다. macOS는 **자연스러운 스크롤**이 켜져 있으면(기본값) 마우스 휠 방향도 뒤집기 때문에, HID 기준으로 "위(+1)"를 보내면 문서가 아래로 갑니다. 펌웨어는 호스트의 설정을 알 수 없으므로 이 상수로 맞춥니다.

| 증상 | 조정 |
|---|---|
| 스크롤 방향이 반대 (자연스러운 스크롤을 끈 맥, Windows, Linux) | `SCROLL_SIGN`을 `1`로 |
| 연속 스크롤이 너무 느리다 | `SCROLL_REPEAT_MS`를 줄입니다 (60~80) |
| 살짝 누르려 했는데 연속으로 넘어간다 | `SCROLL_REPEAT_DELAY_MS`를 늘립니다 (400~500) |

한 번에 여러 칸씩 움직이고 싶다면 `SCROLL_SIGN`을 `-2`, `-3`으로(부호는 그대로) 키우는 방법도 있지만, 대부분의 OS가 자체 스크롤 가속을 적용하므로 반복 간격을 줄이는 편이 자연스럽습니다.

## 절대 좌표 모드 조정

절대 좌표 모드는 손떨림이 커서 위치에 그대로 보이므로 **1€ 필터**로 거릅니다. 움직임이 느릴수록 강하게, 빠를수록 약하게 거르는 필터라 떨림 제거와 반응 속도를 함께 잡을 수 있습니다. 조정하는 순서가 중요합니다.

1. **보드를 화면 한 곳에 가만히 겨눈 채** `ABS_FILTER_MIN_CUTOFF_HZ`를 맞춥니다.
   - 커서가 제자리에서 떨리면 **내립니다** (1.0 → 0.5)
   - 미세 조정이 굼뜨게 느껴지면 **올립니다** (1.0 → 1.5)
2. 그다음 **화면을 빠르게 가로질러 보며** `ABS_FILTER_BETA`를 맞춥니다.
   - 커서가 손을 뒤늦게 따라오면 **올립니다** (0.3 → 0.5)
   - 빠르게 멈출 때 커서가 튀면 **내립니다**

기본값에서 호스트 시뮬레이션으로 확인한 수치는 이렇습니다.

| 상황 | 결과 |
|---|---|
| 정지 시 손떨림 (10Hz, 피크 간 0.4°) | 0.051°로 **7.8배 감소** |
| 60°/s로 화면을 쓸 때 지연 | **0.33°** (고정 1Hz 필터였다면 약 9.5°) |

`ABS_YAW_GATE_DPS`는 이보다 느린 좌우 회전을 각도로 쌓지 않는 문턱입니다. 가만히 있을 때 남은 자이로 오차(±0.1°/s 수준)로 커서가 흐르는 것을 막습니다. 리센터를 했는데도 가만히 둔 커서가 좌우로 천천히 흐르면 올리세요.

## 리포트 주기

[firmware/src/main.rs](../firmware/src/main.rs)의 상수입니다.

```rust
const LOOP_PERIOD_MS: u32 = 10;
```

10ms = 100Hz입니다. IMU 샘플링과 HID 리포트 전송 주기를 겸합니다. 대기 중인 상대 모드에서는 50ms로 늦춥니다 ([절전 조정](#절전-조정)).

루프는 고정 주기(`xTaskDelayUntil`)로 돌아, 처리 시간이나 라이트 슬립에서 깨어나는 시간에 상관없이 이 주기를 지킵니다. 스크롤 반복과 커서 이동량이 틱 단위라 주기가 틀어지면 둘 다 느려지기 때문입니다.

바꿀 일은 거의 없습니다. 올리면(예: 20ms) 커서가 끊겨 보이고, 내리면(예: 5ms) BLE 대역폭과 전력 소모가 늘면서 실제 부드러움은 크게 나아지지 않습니다. 자이로 ODR이 200Hz이므로 100Hz 루프는 항상 최신 샘플을 읽습니다.

## 절전 조정

[firmware/src/power.rs](../firmware/src/power.rs)의 상수입니다. 동작은 [사용법의 절전](usage.md#절전)을 보세요.

| 상수 | 기본값 | 역할 |
|---|---|---|
| `IDLE_AFTER_MS` | 5초 | 이 시간 동안 움직임·버튼이 없으면 대기 (LED 끔, 루프 감속) |
| `DEEP_SLEEP_AFTER_MS` | 10분 | 마지막 사용 후 이만큼 지나면 딥슬립 |
| `UNCONNECTED_SLEEP_AFTER_MS` | 5분 | 호스트에 연결되지 못한 채 이만큼 지나면 딥슬립 |
| `MOTION_DPS` | 2.0 | 이보다 빠른 회전은 사용으로 본다 (커서 데드존과 같은 값) |
| `IDLE_LOOP_PERIOD_MS` | 50 | 대기 중 루프 주기 (상대 모드만) |
| `SLEEP_HOLD_MS` | 2초 | 스크롤 ↑ + ↓를 함께 이만큼 누르면 버튼 딥슬립 준비 (LED 빨강) |

| 증상 | 조정 |
|---|---|
| 잠깐 내려놓았을 뿐인데 딥슬립에 들어가 불편하다 | `DEEP_SLEEP_AFTER_MS`를 늘립니다 |
| 책상 진동에도 자꾸 깨어나 딥슬립에 들지 않는다 | `MOTION_DPS`를 올립니다 (3~5) |
| LED가 너무 자주 꺼진다 | `IDLE_AFTER_MS`를 늘립니다 (전력은 조금 더 씁니다) |

`IDLE_LOOP_PERIOD_MS`를 늘리면 대기 중에 깨어나는 횟수가 줄지만, 움직이기 시작해서 반응하기까지 최대 그만큼 늦어집니다. 버튼은 디바운스 전 핀 상태를 보고 바로 깨어나므로 영향이 적습니다. 절대 모드는 각도를 적분하므로 대기 중에도 늦추지 않습니다.

## 느린 움직임의 정밀도

HID 리포트의 이동량은 정수(`i8`)지만, 느린 움직임은 리포트당 1카운트가 안 됩니다. 이 값을 그냥 버리면 천천히 움직일 때 커서가 아예 안 움직입니다.

`CursorMapper`는 소수점 잔여를 누적해서 다음 리포트로 넘깁니다. 예를 들어 매 리포트 0.4카운트씩 쌓이면 3번째 리포트에서 1카운트가 나갑니다. 덕분에 감도를 낮춰도 세밀한 조작이 가능합니다.

이 동작 때문에 `GAIN`을 아주 낮춰도 커서가 "죽지" 않고 느려지기만 합니다.
